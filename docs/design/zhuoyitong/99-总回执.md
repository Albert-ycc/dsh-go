**11月03日 05:38–06:02 第二轮（包 408e52f2 → e592506b）**：USB 调试打开后覆盖安装成功（按钮仍是「继续安装」），升级保留了 key、设置与 `/root`，引擎页显示运行时 `…-536ee8aa2a40`、DSH 0.2.1-rc.4 / Node 24.22.1、模型列表 2 个。发消息每轮 0.1 秒内「本轮出错了」，详情为 `EACCES: permission denied, link '<rootfs>/root/.dsh/sessions/--root-workspace--/session-…/session.v4.jsonl.zstd.<随机>.tmp' -> '…/session.v4.jsonl.zstd'`。根因：引擎在会话持久化 worker（`dsh-session-persistence-jsonl/lib/worker.cjs`）与会话首次落盘（同包 `index.js`）用 `link(暂存, 正式)` 做「目标不存在才发布」，卓易通的 App 数据目录拒绝硬链接；glibc 路线有 PRoot 的假硬链接兜住，bionic 直跑没有。这个 worker 以 `execArgv: []` 启动，命令行 `--import` 的预加载进不去。修法：`runtime/bionic/link-fallback.mjs` 在 `link` 返回 EACCES / EPERM 时改用 `copyFile(COPYFILE_EXCL)` 再 fsync，目标已存在仍报 EEXIST；经 `NODE_OPTIONS` 加载，主线程、worker 与子进程都生效（`runtime/tests/bionic-link-fallback.test.mjs` 6 项，含 `execArgv: []` worker 与 ESM 具名导入）。顺带修了 `BionicLaunch` 对 callerEnv 不展开占位符：性能规则从 manifest 原串派生 `NODE_OPTIONS` 再覆盖回去，`{ROOTFS}` 会原样留下（`BionicLaunchTest` 新用例，撤掉修复时会失败）。新包装上后会话落盘、标题生成、请求发到模型都通了，模型回「key 无效」；06:01 账号页也显示 key 无效，而 05:43 同一把 key 还查得到余额，账号侧在这十几分钟里停用了它。

**11月03日 22:11–22:29 第三轮（包 e592506b → 7c9a8bde）**：用户换好 key，验收一通过（见第二节）。网页版在容器的华为 HwWebview 里缺新内置：目录选择器报 `AbortSignal.any is not a function`，webserver 自己的启动就绪脚本还调 `Promise.withResolvers`，缺一个就整页卡住。扫了浏览器侧模块，用到的较新内置有 AbortSignal.any / timeout、Promise.withResolvers / try、Array 的 toSorted / toReversed / findLast(Index)、Set 集合方法、Object.hasOwn、URL.canParse、RegExp.escape、replaceAll、Symbol.dispose。修法：dsh-go 桥订阅 `webserver/index-inject`，把 `lib/web-polyfills.js` 作为第一条 head 行插入，逐项检测、原生有就跳过（`runtime/tests/bridge-web-polyfills.test.mjs` 5 项，含在剥掉内置的 vm 里验行为、原生不被替换、渲染后排在就绪脚本之前）。装上后目录选择器正常。22:29 用户叫停验收，转去接 Claude API（设置 → 模型 → 自定义 → 添加渠道，协议选 Anthropic）。渠道建好后发消息报「API Key 无效或已过期」，后端原文是 `403 forbidden / Request not allowed`。对照实测：手机引擎不带 key 请求 `api.anthropic.com/v1/models` 同样 403；Mac 经本机代理（FlClash，`127.0.0.1:7890`，只监听本机）请求得到 401 `x-api-key header is required`。所以拦截在验 key 之前，是 Anthropic 拒绝了手机的国内直连出口，key 本身还没被检查。另外渠道里手动加的模型 ID 是「Opus5.5」，Anthropic 不认，网络通后要换成 `claude-opus-5-5` 这类正式 ID，或用「获取模型」拉列表。App 把 403 也归成「Key 无效」，提示会误导，未改。接通的路待用户定：手机侧开代理（卓易通容器是否走宿主 VPN 未验）、换 Anthropic 兼容的中转地址，或让 Mac 代理对局域网开放后给引擎配 `HTTPS_PROXY`。

## 四、用户要做的事（按顺序）

1. 放行真机：手机插回 USB 或连回同一 Wi-Fi 且无线调试开着、屏幕解锁；主线推新包覆盖安装，再续跑排队的验收；期间尽量别同时操作手机（设备端 uitest 同一时刻只服务一个调用方）。手机上现装的是今天的 debug 签名包，新包同签名可直接覆盖；**不要用官方 release 包覆盖**（签名不同会被拒，且 glibc 的会话不会迁到 bionic）。
2. 验收一的最后一步：现装的 key（尾号 3e4a）已被 DeepSeek 判为无效。在 设置 → DeepSeek API Key 换一把有效 key（或用 DeepSeek 账号登录），回对话页发一条消息看有回复。
3. 在 Mac 上装中继：照 `tooling/dsh-relay/README.md` 八步，`./install.sh --label com.albert.dsh-relay` 并在 shell 里 `export DSH_RELAY_LABEL=com.albert.dsh-relay`（CLI 默认标签是 `local.dsh-relay`，doctor 会查三个标签），端口 8731；`dsh-relay doctor` 现在会查绑定设备在线与令牌数；终端里拿一次性配对码。
4. 手机上 设置 → 手机操控 → Mac 中继：填 Mac 地址与配对码，测试连接。
5. 想让它操作鸿蒙「设置」类页面时，在 手机操控 → 解除限制 里打开「系统设置」（默认按系统页拒绝）。

## 五、已知缺口与后置项

- 不打扰模式本期不做（uitest 只能作用于物理屏）。
- 卓易通上 git / python / curl 不存在：Git 来源插件、python 类插件、本地语音、终端、Office 转换本期拒绝并在界面说明原因。
- 手机操控一步约 4 秒（读屏 1.4 s × 2 + 动作），比安卓真机慢；Wi-Fi 省电会让首个请求超时，中继有重试。
- 密码框只能靠 hint 关键词与输入法「安全键盘」信号识别，输入后是掩码还是明文无样本。
- 中继令牌经 Keystore 加密落盘，但同 uid 原生代码理论上仍可走 keystore2 解密，应用内堵不了；自连 ADB 私钥仍明文落盘（既有）。
- P4 后置：M6 解包树可写且哈希只写不验、L1–L8（M5 已在 P5 收掉）。
- P5 后置：侧栏终端 / persistent-bash 在 bionic 下不可用（`/bin/bash` 与 node-pty 无 android-arm64 预构建，标准 bash 工具不受影响，走包装脚本到 mksh）；LKG 文件与日志目录两族共用；`libdsh_node.so` 内嵌构建机绝对路径（下次重编 node 加 `-fdebug-prefix-map`）；pnpm vendor 带两个 Windows PE；用 workspaceId 建的会话 header 里 cwd 仍是物理路径；中继 `unhandledRejection` 兜底无单测、kick 失败日志只记变化、launchd 固定 10 秒退避且 launchd.log 不轮转；toolchain 脚本下载中断不校验半截文件；`RuntimeStatus.engineFamily` 默认 glibc 造成首屏几十毫秒语音行闪现。
- 从官方 1.0.9（PRoot）升级到本包：签名不同会被系统拒绝；即使装上，`/root` 不会从 glibc 迁到 bionic。只支持卸载后全新安装。
- 真机才能验的 8 条见 `P5-深度审查.md` 第四节（容器 Keystore 可用性、覆盖安装按钮文字、回车在非搜索框的行为、包装脚本 exec 与 mksh / tzdata、`/sdcard` 可见性、Wi-Fi 省电与 hdc 唤醒恢复、系统 bundle 名、launchd 网络权限）。
- P2-c 留的两处文案：进阶卡里「后台运行」「后台确认与返回」在容器上的去留、手机操控关闭态三行介绍仍提无障碍。
- 旧语音路线「引擎」的存值在切到 bionic 后未清理。
- 待真机核对的 bundle 名：`com.ohos.systemui`（下拉通知/控制中心）、`com.alipay.mobile.client`、`com.tencent.wechat`、`com.huawei.hmos.wallet`。
- `node --test runtime/tests/*.test.mjs` 不带 `DSH_PREFIX` 时 13 份测试因缺补丁引擎树失败；带 `DSH_PREFIX=~/workspace/dsh-go-wt/p2-1/base` 时 442 项过 436，余 4 项与本次改动无关：`fs-create-exclusive` 在该树里找不到 `@deepseek-ai/cordis`、`file-upload-resolver` 要在 Mac 上起 Host 但该树没有 `node-addon-require-builtin-darwin-arm64`（它是 android 过滤版）、`native-capabilities` 的 NJS3 两项是时序断言；要全绿得用未过滤的 darwin 引擎树。
- 家族之间不迁移会话与设置；回退后 glibc rootfs 留给「重置运行环境」清理。
