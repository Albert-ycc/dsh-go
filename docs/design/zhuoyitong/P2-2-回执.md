## 体积（P1 第 11 节决定 1 的复核）

1.0.9 的 arm64 APK：206,084,141 字节（`gh release view v1.0.9`，196.5 MiB）。本机无法产出带 glibc 的 APK，所以用增量法：同一 APK 里 bionic 部分的实测占用（zip 内压缩后）：

| 项 | APK 内字节 |
|---|---|
| `engine-arm64-v8a.tar.xz`（已是 xz，zip 存储） | 30,552,148 |
| `libdsh_node.so`（66,279,784 未压缩，deflate） | 22,667,517 |
| `libdsh_sysprobe.so` + `manifest.json` | 1,930 + 2,181 |
| 合计 | 53,223,776（50.8 MiB） |

推算：206,084,141 + 53,223,776 ≈ 259.3 MB，比 1.0.9 大 25.8%，低于「超出 40% 再议拆包」的线（288.5 MB）。这是推算：1.0.9 与当前工作树的 Dart/Kotlin 代码不同，APK 其余部分有几 MB 浮动；P1 估的「+50–60 MiB」与实测 50.8 MiB 相符。node 的 libdsh_node.so 实际 deflate 到 34%，没有按 P0A 估的 80 MB 计。

## 未运行 / 未验证

- NOT_RUN：任何真机项。探针 ELF 只做了静态检查（AArch64、PIE、interp `/system/bin/linker64`、LOAD 对齐 0x4000、NEEDED 仅 libc/libdl）；其判定逻辑用 `-DPROBE_FAKE` 在 macOS 宿主上跑了 allowed→退出码 0、sigsys→42、segv→43 三种；真实的 `syscall(99)` 在被过滤器杀的设备上没有跑过。
- NOT_RUN：S10（bionic `system.node` 在容器里 `dlopen`）、S11（rg 在容器内可运行）。补丁测试 `bionic-patches.test.mjs` 本次 6 通过 1 跳过（`FLOCK_REAL_NODE` 未设，真实抢锁用例跳过）。
- NOT_RUN：把归档交给 Kotlin `TarExtractor` / `ParallelXZInputStream` 解开。归档只用 macOS `tar -xJf` 和 Python tarfile 解过；格式与 `rtbuild.py assemble` 同为 GNU tar、相对名、仅目录 / 常规文件 / 符号链接，xz 为多线程块。
