## 2. 实现中与 P1 的出入

- `UV_USE_IO_URING=0` 按 T1 README 设上（固定变量，先于 `launch.env`），与 P1 3.6「不需要」冲突处按「设上无害、防升级」处理。
- `DSH_GO_RUNTIME_ROOT` 最后写入，调用方环境不能覆盖：清理扫描靠它认领进程。P1 3.4 的覆盖顺序对其余变量不变。
- `pnpx` 包装脚本指向 `pnpx.mjs`（P1 表里两个都写 `pnpm.mjs`，同 Direct 的 `bin/$name.mjs`）。
- `dsh-web.patch.yml`（fallbackRegistries + 桥的 insert）由 `BionicLaunch.prepare` 每次启动写，P2-2 的 `rtbionic.py` 没有把它烤进归档，两边一致〔读码〕。
- 探针契约按 P2-2 已落盘的 `probe.c`：无参数 exec，退出码 0 放行 / 42 SIGSYS / 43、44、45 其它；43–45（含协调方所说的 43）在 Kotlin 里读作 UNKNOWN。额外把退出码 159（探针进程自己被 SIGSYS 杀）读作 CONFINED。stdout 一行只进日志。
- 回退触发用原始 `exitCode == 159 && readyAt == null`，不经分类器：`DirectFailureTest` 要求 PRoot 的 159 仍是 `KILLED`，没有放宽。PRoot 下 proot 自己的退出码形态仍待 S17 标定。
- 回退只在选项为 `auto`、bionic 包存在、运行的是 glibc 时触发；bionic 失败不会回切。

## 4. 判定标准逐条

1) 对勾。`BionicLaunchTest` 对 argv、env 整表、cwd 逐项断言，来源是 P1 3.3 的 `launch` 段原文、3.4 的变量表、3.5 的包装脚本：
 - argv：`/system/bin/sh -c 'echo $$ > "$0" && exec "$@"' <rootfs>/tmp/dsh-web.pid <nativeLibDir>/libdsh_node.so --expose-internals <rootfs>/opt/dsh/.../bin.js web --patch <rootfs>/etc/dsh-app/dsh-web.patch.yml [--patch 各 overlay] --host 127.0.0.1 --port N --no-open`，`--expose-internals` 在 argv 不在 `NODE_OPTIONS`；
 - env：固定 8 项 → `launch.env` 6 项 → 调用方（`TZ`、`UV_THREADPOOL_SIZE`）→ `DSH_GO_RUNTIME_ROOT`；无 `LD_LIBRARY_PATH / LD_PRELOAD / NARB_DISABLE_NATIVE_CACHE / PROOT_*`；
 - cwd：`<rootfs>/root`；
 - 安全模式：`--profile dsh-app-safe --from-default-profile web --patch <物理 overlay>`，不带额外 overlay，模板缺占位符时拒绝启动；
 - 包装脚本逐字节、可执行位、重写幂等、`nativeLibraryDir` 变化后跟随。

2) 对勾。`DirectLaunchTest` 22/22、`Issue24LaunchFailureTest` 5/5、`CrashClassifierTest` 8/8、`RuntimeResetKeepTest` 19/19、`RuntimeHomeSwapTest` 2/2，〔实测〕。另 `DirectFailureTest`、`LaunchDiagnosticsTest`、`GuestPathsTest`、`ProcessLaunchGuardTest` 全绿。

3) 对勾，JVM 层。`EngineFamilyTest.aGlibcStartKilledBySigsysBeforeReadyWritesTheMarkerAndSwitchesTheFamily`：glibc 状态下 `fellBack(GLIBC, 159, null)` → 偏好里写入 `engine_family_auto_bionic = <glibc runtimeVersion>` → `decision == (BIONIC, "fallback")`。配套用例：标记跨进程重启保留、glibc runtimeVersion 变了就失效、已就绪的 159 / 其它退出码 / 运行的是 bionic / 显式选 glibc / 无 bionic 包都不触发。`RuntimeController.onExit` 调用的就是这个 `State.fellBack`，之后的 `notice → install → restartNow` 链路依赖 Android 上下文，NOT_RUN。

4) 对勾。`status()` 含 `engineFamily / engineFamilyAvailable / engineFamilyOverride / engineFamilyReason`，字段名与 `app/lib/runtime/runtime_bridge.dart` 一致〔读码〕；glibc（`decide` 默认分支与 `bionicAvailable=false` 分支）下 `engineFamily = "glibc"`，`directEngineAvailable` 在 bionic 下为 false。`status()` 本身依赖 `Context`，没有 JVM 用例，字段取值由 `EngineFamilyTest` 的 `decide` 表覆盖，装配是读码结论。

5) 日志点已埋，真机项 NOT_RUN，见第 5 节。

## 5. 给 P3 真机验收（S15、S16、S17）的操作

强制 bionic（任选）：
- 诊断页开发者选项里的「运行环境」三态（P2-4 的界面，调 `setEngineFamily {family: 'bionic'}`）；
- 〔推断，未验〕debug 包：`adb shell run-as io.github.ccch1mneyyy.dsh_app` 编辑 `shared_prefs/dsh_runtime.xml`，加 `<string name="engine_family_override">bionic</string>`，强停 App 重开。

要看的日志（诊断页「引擎日志」或 `files/runtime/logs/dsh.log`，bionic 与 glibc 共用同一份）：

| 日志 | 含义 |
|---|---|
| `[dsh-app] syscall probe: <open\|confined\|unknown> (exit N, <探针那一行>); selinux=... fingerprint=...` | 首次启动一次，按指纹缓存；`selinux` 已判定受限时不会跑 |
| `[dsh-app] engine family: <family> (<reason>)` | `setEngineFamily` 或探针改判之后 |
| `[dsh-app] engine family: bionic (<reason>); selinux=... fingerprint=...` | 每次 bionic 启动前，记原因 |
| `[dsh-app] unpacking runtime bionic-... (arm64-v8a)`、`install verify / extract / activate / sync: N ms`、`runtime ready in Ns` | S15 的 install 耗时 |
| `[dsh-app] launch method: bionic` 与 `launching /system/bin/sh -c ... libdsh_node.so --expose-internals ...` | 实际 argv（token 类键已打码） |
| `[dsh-app] DSH is listening at ...` 与 `StartupTimeline` 一行 | 点击到 token 行的耗时 |
| `[dsh-app] DSH exited with code N`、`classified as launchFailed/killed ...` | 失败形态；`CANNOT LINK EXECUTABLE`、`sh: ...: inaccessible or not found` 等措辞用来校准 `CrashClassifier.BIONIC_FAILED` |
| `[dsh-app] glibc engine killed by the system call filter before it was ready (exit 159); switching to the bionic engine` | 自动回退触发 |

峰值内存不在应用日志里：启动期间 `adb shell dumpsys meminfo <包名>` 取。

S15 之外的两项：
- S17：自动模式关掉（先把选项设成 `glibc`），分别用 PRoot 与 Direct 启动，记录 `DSH exited with code N` 与日志尾部，据此定稿 proot 下 SIGSYS 的退出码；如果 proot 退出码不是 159，`EngineFamily.shouldFallBack` 与 `fellBack` 的触发条件要改（一处）。
- 自动回退整链：选项设 `auto`，在 SELinux 域不受限而 glibc 会被杀的机器上才能走到；卓易通本身因 SELinux 域直接判 bionic，不会走回退，这条链需要另一台受限但域名不同的设备，或在 debug 下手动把偏好 `engine_family_auto_bionic` 清掉后用 `glibc` 选项观察 S17 的失败形态。

## 6. 待拍板

1. glibc 与 bionic 各有一份 `root/`（会话、插件、`.dsh` 设置），切换 family 不迁移。卓易通上 glibc 从未跑起来，没有数据可迁；但手动在可跑 glibc 的手机上切到 bionic 会看到空白家目录。是否要在设置里提示，或做一次性拷贝（拷贝要避开 PRoot 假硬链接，成本不小）。
2. 自动回退成功后，glibc rootfs（约 750 MB）仍留在 `filesDir/runtime/`。要不要在回退后给一个清理入口，或自动 `reset`（破坏性，需要确认）。
