### 2.12 真机首轮（15:19–15:36）：引擎就绪，新建对话失败

- 15:19–15:23 在卓易通桌面长按卸载官方 1.0.9（`uninstall-0-container`、`uninstall-1-menu`、`uninstall-2-confirm`、`uninstall-3-done`）〔实测〕。
- 15:25 文件管理器点 `dshgo-p3.apk` 进入安装提示页（`install-1-prompt`）；之后用户自己完成安装、首启选本机并填了 DeepSeek API key（设置页 key 卡片显示余额）〔实测，P3 读屏〕。
- 引擎页（`s3-engine`、`s4-log1`–`s4-log4`）〔实测〕：「本机引擎 · 运行中 · 127.0.0.1:3080」，DSH v0.2.1-rc.4，Node.js v24.22.1；日志 `DSH is listening at http://127.0.0.1:3080`、`startup: prepare 78 ms, dsh 2749 ms`、`[llm-deepseek-api-key] model listing from https://api.deepseek.com/models loaded 2 model(s)`、`DSH has been up for 2 minutes; recorded its plugin set as the last good one`。说明 bionic 引擎进程、桥、TLS 出网、key 都正常。
- 对话页输入「早上好」发送，红条「新建对话失败」，无附加原因（`user-newchat-fail.jpeg`）〔实测〕。
- 根因〔读码〕：`app/lib/state/sessions_state.dart:561` 给本机会话发 `session/create` 时 `cwd` 固定为 `/root/workspace`；引擎的 `zz-direct-runtime.diff` 只在 `globalThis[Symbol.for("dsh.go.direct")]` 存在时把 guest 路径映射成物理路径（`dsh-api-session-controller` 的 `createAgent` → `prepareDirectory` → `mkdir`）；Direct 模式由 `runtime/direct/preload.mjs` 装这个适配器，bionic 模式没装，`/root/workspace` 原样 `mkdir` 失败，错误码不在 `chatErrorText` 的映射表里，所以界面只显示动作名。P1 §2 第 2 条「bionic 不做 `/root` 映射」的依据不成立，见 P1 §11 决定 5。
- 修法：运行时新增 `runtime/bionic/{paths,preload}.mjs`（只映射与 Kotlin `GuestPaths.MAPPED` 相同的八个 guest 前缀，`/sdcard`、`/system`、`/data` 原样，子进程不接管），归档 `opt/dsh-go/bionic/`，`launch.argv` 加 `--import`。`node --test runtime/tests/bionic-paths.test.mjs` 6 项通过（含真实 `--import` 加载）。新运行时 `bionic-r1-dsh0.2.1-rc.4-node24.22.1-b61cbc5e2152`（归档 29.1 MiB xz / 177.7 MiB 解包），新 APK 见下一节表头；安装走升级路径（`RuntimeInstaller` 换 rootfs、保留 `/root`），复验点：建会话成功、首条消息有回复、`/root/workspace` 下文件工具可读写、升级后 key 与设置仍在。
- 15:36 后真机验收被用户叫停（P3 agent 与 hdc 服务停止），复验等用户放行。
