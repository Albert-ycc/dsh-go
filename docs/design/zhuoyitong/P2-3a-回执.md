## 2. 映射规则

- 前缀（最长优先）：`/opt/dsh-app`、`/opt/dsh-go`、`/opt/dsh`、`/opt/pnpm`、`/etc/dsh-app`、`/var/lib/dsh-app`、`/root`、`/tmp`。比 P1 3.7 多了 `/opt/pnpm`（3.5 的 pnpm 包装脚本路径）与 `/tmp`（SafeMode 简报里的 `/tmp/dsh-web.pid`，3.4 的 pid 文件在 `<rootfs>/tmp`）。
- 命中条件：前一个字符不在 `[\w./~-]`，后一个字符不在 `[\w-]`。`/usr/local/bin/dsh`、`/sdcard/...`、`/rooted`、`/opt/dshx`、`x/root/y`、`https://h/root/a` 不动。
- 幂等：物理前缀自身是正则的第一个分支，原样吞掉。因此 `<rootfs>` 本身以 `/tmp`、`/root`、`/opt/dsh-app` 开头时也不会二次改写（用例 `isIdempotentEvenWhenTheRootfsStartsWithAMappedPrefix`）。
- 前缀取 `rootfs.canonicalPath`，与 `GuestSetup` 的 Direct 分支一致。

## 4. 判定标准

1) `IDENTITY` 下既有 JVM 测试结果不变：全量 819/820 通过，唯一失败见上，与本次改动无关。`IDENTITY.text(s)` 返回同一个对象（用例 `identityLeavesEverythingAlone`），SpeechGuest 与 GuestSetup 另有「恒等写出与原常量逐字节相同」的断言。

2) 非恒等时幂等且路径全部替换：`GuestPathsTest.assertMapped` 对每份文本同时断言 `text(text(x)) == text(x)` 与「不残留未前缀的 guest 路径」，覆盖 PhoneGuest.PATCH_YAML、RELAY_JS、SessionSearchGuest.PATCH_YAML、AppAuthGuest.PATCH_YAML；SafeMode 覆盖 `prepare` 写出的三个文件和 `profileArg`/`guestEnv`；GuestSetup 覆盖 bionic 与 proot 两份 AGENTS.md。已逐项断言的具体值：`relay.cjs` 的 `bridge.json` 缺省路径、`session-search.sqlite`、`auth/index.mjs`、`overlay.patch.yml` 的 `--patch` 实参、`DSH_AGENTS_HOME`、`dsh-app-plugins` 的三个缺省路径、简报里的 `/tmp/dsh-web.pid`。

## 5. 给 P2-3b 的签名

```kotlin
class GuestPaths private constructor(prefix: String?) {
    val rootfs: String?              // 物理 rootfs 路径，IDENTITY 为 null
    val isIdentity: Boolean
    fun text(s: String): String      // 整段文本，幂等
    fun path(guestPath: String): String
    companion object {
        val IDENTITY: GuestPaths
        fun bionic(rootfs: File): GuestPaths
    }
}

PhoneGuest.patchYaml(paths: GuestPaths = IDENTITY): String
PhoneGuest.writeFiles(rootfs: File, paths: GuestPaths = IDENTITY)
SessionSearchGuest.patchYaml(paths = IDENTITY): String
SessionSearchGuest.writeFiles(rootfs: File, paths: GuestPaths = IDENTITY): Boolean
AppAuthGuest.patchYaml(paths = IDENTITY): String
AppAuthGuest.writeFiles(context: Context, rootfs: File, paths: GuestPaths = IDENTITY): Boolean
SpeechGuest.patchYaml(paths = IDENTITY): String
SpeechGuest.writeFiles(rootfs: File, paths: GuestPaths = IDENTITY): Boolean
SafeMode.profileArg(arg: String, safe: Boolean, paths: GuestPaths = IDENTITY): String?
SafeMode.guestEnv(paths: GuestPaths = IDENTITY): Map<String, String>   // GUEST_ENV 仍是恒等值
SafeMode.prepare(rootfs: File, briefing: Briefing, paths: GuestPaths = IDENTITY)
GuestSetup.writeAgentsMd(rootfs, phoneStorage, phoneControl = false, visualReplies = true,
    directEngine = false, bionic = false, paths: GuestPaths = IDENTITY)
GuestSetup.BIONIC_AGENTS_MD   // internal
```

调用约定：bionic 启动时 `val paths = GuestPaths.bionic(installer.rootfs)`，对上列各调用传 `paths`，`writeAgentsMd` 同时传 `bionic = true`。`SessionSearchGuest.file(rootfs)`、`AppAuthGuest.file(rootfs)`、`SpeechGuest.file(rootfs)` 返回的仍是 rootfs 内的物理文件，组装 `--patch <abs>` 时用 `paths.path(XxxGuest.PATCH)`。`launchArg` 系列未动（bionic 不用，见 P1 3.7）。

## 6. 待拍板

1. `SafeMode` 简报里「不要改 `/opt/dsh`、`/opt/node`」的 `/opt/node` 在 bionic 下不存在（node 是 jniLibs 里的 `libdsh_node.so`），映射表也没收它，简报会带着一个不存在的路径出现。要不要在 P2-3b 里给 bionic 另写这一行，还是容忍。
