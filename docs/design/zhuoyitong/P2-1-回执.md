3) 对勾。命令：`DSH_PREFIX=…/base FLOCK_REAL_NODE=<darwin system.node> node --test runtime/tests/bionic-patches.test.mjs`，7/7 通过：
```
✔ pins 链：bionic 的 before 等于主目录链条终点，补丁树文件等于 after
✔ E1：--expose-internals 下 internalModules() 返回 esm / cjs 形状
✔ E1：没有 --expose-internals 时仍走 node-addon-require-builtin（glibc 路径不变）
✔ E2：android 平台下 flock.js 加载 bin/bionic/system.node（替身 .node，验路径解析与调用）
✔ E2：未打补丁的 flock.js 在 android 上仍拒绝（反向守卫）
✔ E2：真实 .node 加载并抢锁（FLOCK_REAL_NODE 替身，非 bionic 产物）
✔ system.node：NDK 现编，无 NEEDED libnode，…，同输入两次逐字节相同
```
- E1 用例从补丁后的 `dsh-app-boot/lib/index.js` 里切出 `internalModules()` 原文，放进临时 .mjs，在 `node --expose-internals` 下真实执行；函数自带的形状校验（`resolveSync`、`getOrCreateModuleJob`、`_resolveFilename`、`getCjsConditions`、`defaultResolve`）通过，返回键为 `cjs, cjsConditions, esm, esmConditions, esmDefaultResolve, modern`。附录 B 的假设「`createRequire(...)('internal/...')` 在 `--expose-internals` 下可用」在本机 Node 24.13.1 上成立（实测）；目标 24.22.1 的 S1 仍要在真机上过。
- E2 有两种加载：替身用例改写 `Module._extensions['.node']`，断言被加载的路径恰为 `…/node-addon-system-android-arm64/bin/bionic/system.node`，并验证 `tryLockExclusive` 的成功与 EAGAIN 错误形状；真实加载用例把 darwin 版 `system.node`（`npm pack @deepseek-ai/node-addon-system-darwin-arm64@0.1.2`）放进同一路径，两个 fd 对同一文件，第二次抢锁得到 EAGAIN。bionic 的 `.node` 在 macOS 上无法 dlopen，没有真实加载过，这一步归真机 S10。
- 反向验证（实测）：对未打补丁的 `glibcref` 跑同一测试，pins 链、E1 形状、E2 替身三项变红，其余绿；说明测试能抓到补丁缺失。

4) 对勾。`build-flock.sh` 用 NDK 28.2.13676358 的 `aarch64-linux-android26-clang` 编出 8,656 字节的 stripped ELF，AArch64。
```
exported : napi_register_module_v1, node_api_module_get_api_version_v1
NEEDED   : libdl.so, libc.so        （无 libnode）
undefined: napi_* 共 23 个，与 darwin 版逐个同名，其余 __cxa_atexit/__cxa_finalize/__errno/__register_atfork/calloc/flock/free，全为 @LIBC
sha256 7f9b9f2957e40bb1a1c6f755aee26ef50100bd9ca224104be0fbed0ea93d00f6   同输入两次构建相同
```
实测。`__cxa_*`、`__register_atfork` 来自 NDK 的 crtbegin，属 libc；`libdl.so` 是 bionic 自带库。`flock-android.c` 是按接口重写，不是拷贝上游 `flock.c`（上游 LICENSE 为 MIT、package.json 写 BSD-3-Clause，两处不一致）；napi 符号集合与 darwin 版相同，行为没有逐位对照上游产物。

## 需要 P2-2 注意

- `rtbuild.py patch-dsh` 不递归，bionic 构建要调两遍：`--patches runtime/patches` 再 `--patches runtime/patches/bionic`，无需改 `rtbuild.py`。第二遍的 `pins.json` 链接在第一遍终点上；顺序反了会报 `differs from the vetted…`。
- `build-flock.sh` 的输出是单个 `system.node`；平台包 `node-addon-system-android-arm64` 的 `package.json` 与 `bin/bionic/system.node` 布局由 `rtbionic.py` 创建，E2 补丁固定读 `bin/bionic/system.node`。
- `--expose-internals` 必须写在 node 的命令行参数里；放进 `NODE_OPTIONS` 时 `process.execArgv` 不含它，E1 会落回原分支并因缺包抛 MODULE_NOT_FOUND。
