# P3 手机操控验收（Mac 中继 × 鸿蒙卓易通）

验收依据：`P1-架构-手机操控中转.md` 第 8 节 R0–R13 与第 12 节主线决定。脚本：`tooling/dsh-relay/e2e/run-e2e.sh`。

状态标记：〔实测〕〔读码〕〔推断〕NOT_RUN。本文件当前处于阶段 A：脚本与骨架完成，用假 hdc 演练过脚本；真机项全部 NOT_RUN。

## 1. 验收口径与偏差

口径取第 8 节：R0–R3、R6–R8 全过，R4、R5 被拒，R9–R13 记录实测；R5 若拦不住（密码被打进去）升级为阻塞项。

与第 8 节原文不同的执行方式：

| 项 | 原文 | 本次做法 | 原因 |
|---|---|---|---|
| 前置 | `install.sh --label com.albert.dsh-relay` 装 launchd | 前台进程起中继，HOME 用默认 `~/.dsh-relay` | 验收位不得装常驻作业；之后用户按 README 装 launchd 时复用同一份证书与令牌，配对不用重做 |
| R0 | `doctor` 全部通过 | 除 `launchd job` 一行外全部通过 | 未装 launchd，该行必然 FAIL；`E2E_ALLOW_LAUNCHD=0` 可改为必过 |
| R8 | `launchctl bootout / bootstrap` | 杀掉并重起前台进程 | 同上；行为差异只在进程管理方式，端口、证书、令牌、手机侧表现相同 |
| R9 | 拔 USB 并关无线调试 | 只记录当前通道；USB 侧由用户协调，否则 NOT_RUN | 关无线调试属于改手机系统设置 |
| 示例任务 | R3「打开设置，把蓝牙关掉」 | 「打开计算器算 12 乘 34」或「打开备忘录新建一条写今天日期」 | 第 12 节决定 1：鸿蒙设置按系统页硬拒；「关蓝牙」由用户在 解除限制 里开启「系统设置」后另验 |
| 令牌 | | 令牌不进任何输出、日志、文档 | 脚本只把令牌写入 0600 临时文件，请求头走 `-H @file` |

## 3. 脚本

`tooling/dsh-relay/e2e/` 下：

| 文件 | 作用 |
|---|---|
| `run-e2e.sh` | 验收脚本。环境变量见文件头注释；`E2E_ONLY="R0 R2"` 选项；退出码 0 表示无 FAIL |
| `logq.mjs` | 查 `relay.log`（按行号之后、按键值过滤） |
| `payload.mjs` | R10 请求体与期望 argv |
| `start-relay.sh` | 后台起前台形态的中继并记 pid（不碰 launchd） |
| `fake-instance.sh` | 用 testkit 假 hdc 起 38731 临时实例，HOME 与日志目录在临时目录，演练脚本用 |

脚本覆盖与人工划分：

| 项 | 脚本断言 | 必须人工 |
|---|---|---|
| R0 | `doctor` 逐行、`/v1/ping` 精确返回 | |
| R1 | 日志有配对成功行（`kind:"auth",op:"pair",ok:true`）、`tokens.json` 权限 600、配对码不在日志 | 手机填地址与配对码、点测试连接、看机型/通道/前台应用 |
| R2 | `observe` 200；日志行 `kind:"read",op:"observe"` 含 `nodes`、`bytes`、`ms`，字段全在白名单内（无文字） | 手机操控页点「读一下当前屏幕」看返回 |
| R3 | | 全部（对话驱动、独立核对 `dumpLayout`） |
| R4 | | 全部（读 `relay.log` 确认 2 秒内无 `act`） |
| R5 | | 全部 |
| R6 | `/v1/stop` 取消在途命令（`cancelled>=1`）、在途请求得 409 `cancelled`、`ctl,op:stop` 行、之后 2 秒无 `act` | 通知上的「停止操作」按钮点击 |
| R7 | `halt` 后 observe/act 为 423 `halted`、无设备命令（假设备下假 hdc 零调用）、`resume` 后同一令牌恢复 | 任务进行中的时机（对话里跑着时 halt） |
| R8 | 杀进程后 5 秒内连不上；重起后同一令牌 observe 成功 | 手机「连不上 Mac 中继」通知、页面该行变红 |
| R9 | 真机：记录当前通道与绑定；假设备：hdc 回 `Connect server failed` 时 503 `device_offline`、`target set/auto` 各有 `ctl,op:target` 行、恢复后读屏成功 | 拔 USB、关无线调试、手机页填新地址（用户协调） |
| R10 | 设备端 argv 与原文逐字一致、日志文本位为 `<text:N chars>`、控制字符 422、注入的 `touch` 未执行 | 设备上显示原文（备忘录里肉眼看）；真机需先聚焦输入框并设 `E2E_ALLOW_TYPE=1` |
| R11 | 无令牌 5 次 401 + 第 6 次 429；`auth_fail` 行带来源 IP；无 `X-Dsh-Relay` 头 403；61 秒后解封 | 从另一台局域网设备（手机浏览器或第二台电脑）补一次 |
| R12 | | 全部 |
| R13 | | 全部 |

R11 会把来源地址封 60 秒，脚本把它排在最后；连续两次执行之间至少隔 60 秒，否则自配对一步也会被拒。

## 5. 脚本自检（阶段 A，假 hdc，临时实例 38731）

环境：`fake-instance.sh start` 起实例，端口 38731，HOME 与日志目录都在临时目录；`HDC_BIN` 指向 `testkit/fake-hdc.mjs`；手机未碰。

〔实测〕语法与静态检查：`bash -n` 对 `run-e2e.sh`、`fake-instance.sh`、`start-relay.sh` 通过，`node --check logq.mjs payload.mjs` 通过。本机没有 `shellcheck`，未运行。

〔实测〕`E2E_FAST=1 bash run-e2e.sh`（第一次演练，R11 不等解封）与不带 `E2E_FAST` 的完整一遍，后者摘要：

```
PASS  R0   doctor 全部通过，ping 正确（doctor 退出码 1，仅 launchd 一项未装）
PASS  R1   有配对成功行；tokens.json 权限 600；配对码不在日志
PASS  R2   observe 成功；日志含 nodes/bytes/ms，字段全在白名单内（无文字内容）
PASS  R6   stop 取消 1 个在途命令，在途请求得 409 cancelled，之后 2 秒无 act
PASS  R7   halt 期间 423 halted 且无设备命令（假 hdc 零调用）；resume 后同一令牌恢复
PASS  R8   停进程后 0s 内连不上；重起后原令牌与证书继续有效，无需重新配对
PASS  R9   离线 503 device_offline；target set/auto 各有 ctl,op:target 行；恢复后读屏成功
PASS  R10  含引号与 $() 的文本以单个原样 argv 到达设备端；日志只有字数；控制字符被 422 拒绝；注入命令未执行
PASS  R11  未带令牌 401×5 后第 6 次 429；auth_fail 带来源 IP；61 秒后解封，合法令牌恢复
PASS  LEAK relay.log 中无令牌明文
=== 汇总: PASS=10 FAIL=0 SKIP=0
```

关键日志行（脱敏字段已是日志原样）：

```
{"kind":"read","op":"observe","nodes":8,"bytes":2522,"dev":"usb:FAKE-USB-0001","ms":161,"ok":true}
{"kind":"ctl","op":"stop","cancelled":1,"ok":true}
{"kind":"act","op":"text","args":{"op":"text","textChars":18},"cmd":"uitest uiInput text <text:18 chars>","ok":true}
{"kind":"auth","op":"auth_fail","ip":"127.0.0.1","path":"/v1/observe","ok":false}
```

〔实测〕负向演练（证明脚本会报 FAIL）：
- 中继进程停掉后跑 R0、R2：`FAIL R0 doctor 有未通过项: service (ctl port) ... ECONNREFUSED`，`FAIL SETUP ping ... 失败`。
- 来源已被 R11 封禁时紧接着再跑：`FAIL SETUP 拿不到令牌`（自配对被拒）。

〔读码〕没有负向演练的断言：R2 字段白名单（日志行出现额外字段才 FAIL）、R6 的 409 `cancelled`、R10 的 argv 逐字比较与 canary 文件。这些分支未被故意触发。

〔读码〕`E2E_TOKEN_FILE` 路径（外部给令牌）未演练；脚本自配对路径已演练。

假设备与真机的差异会影响判读：R6 的在途命令靠假 hdc 注入 4 秒延迟，真机上靠 `observe` 本身约 1–2 秒，`stop` 在 1 秒后发出，真机独占环境下 `observe` 若在 1 秒内完成则 `cancelled` 为 0，R6 会 FAIL，此时需看日志是否为时序问题后重跑。R9 的离线用 hdc 回显 `Connect server failed` 模拟，不等于真正拔线后的 `hdc list targets` 变化。
